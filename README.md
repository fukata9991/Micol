# Micol
動画ストリーミングアプリ

PC 内のフォルダを参照して、動画をフォルダ構成のままブラウザで一覧・再生できるツールです（Jellyfin のフォルダ表示のようなもの）。
同じ LAN 内のスマホやタブレット、別の PC からも視聴できます。

## 必要なもの

- Windows 10 / 11
- [Node.js](https://nodejs.org/) 20.11 以降
- [FFmpeg](https://www.gyan.dev/ffmpeg/builds/)（`ffmpeg` と `ffprobe` に PATH が通っていること）

npm パッケージのインストールは不要です。

## 起動

`start.bat` をダブルクリックするか、次のコマンドを実行します。

```
npm start
```

起動後、ブラウザで http://localhost:8420 を開きます。
コンソールに表示される `LAN : http://192.168.x.x:8420` を開くと、他の端末から視聴できます。
（初回起動時に Windows ファイアウォールの確認が出たら「プライベート ネットワーク」を許可してください）

## 使い方

1. 初めて開くと「管理者アカウントを作成」画面になるので、ユーザー名とパスワードを決めます
2. 左側のサイドバー（狭い画面では左上の ≡ で開きます）の「設定」から、動画フォルダを追加します（「参照…」でフォルダを選べます）
3. ホームにライブラリが表示されるので、フォルダをたどって動画を選びます
4. フォルダ内の追加・削除は自動で検出されます

### ログインとユーザー

動画・サムネイルを含むすべての機能は、ログインしないと使えません。

- **最初の管理者**は、セキュリティのため、サーバーと同じ LAN 内から直接アクセスしたときだけ作成できます
  （Cloudflare Tunnel などインターネット経由では作成できません）
- **ユーザーの追加**は、設定画面の「ユーザー」から行います（管理者 / 一般）
- **管理者**だけが、設定の変更・ユーザー管理・アップデート・サムネイルの変更をできます
- **視聴履歴**（続きから再生・視聴済み）はユーザーごとに記録され、サイドバーの「履歴」で確認・削除できます
- パスワードは右上のアカウントアイコン →「アカウント・パスワード変更」から変更できます。変更すると、他の端末ではログアウトされます
- ログインに 5 回続けて失敗すると、その接続元からは 5 分間ログインできなくなります

パスワードを忘れた場合は、次のどちらかで対応します。

- 他の管理者がいれば、設定画面の「ユーザー」から「パスワード再設定」を行う
- 管理者が 1 人だけの場合は、サーバーを止めて `data/users.json` と `data/sessions.json` を削除し、
  サーバーを起動してから LAN 内で管理者を作り直す（ライブラリ設定は残ります。視聴履歴は新しい管理者には引き継がれません）

### 画像・字幕・NFO の置き場所

動画ごとの付属ファイルは、動画フォルダ内の `.thumbs` / `.nfo` / `.trickplay` フォルダにまとめます。
（先頭が `.` のフォルダは Micol のフォルダ一覧には表示されません）

```
アニメ\
  動画名.mp4
  動画名.srt                          ← 外部字幕は動画の隣
  .thumbs\動画名.jpg                  ← サムネイル
  .nfo\動画名.nfo                     ← NFO
  .trickplay\動画名.trickplay\…       ← シークバーのプレビュー
```

| 種類 | ファイル名の例 |
| --- | --- |
| フォルダの画像 | `poster.jpg` / `folder.jpg` / `cover.jpg`（無い場合は中の動画のサムネイル） |
| 動画の画像 | `.thumbs\動画名.jpg`（無い場合は自動生成） |
| 外部字幕 | `動画名.srt` / `動画名.ja.srt` / `動画名.ass` / `動画名.vtt`（Shift-JIS も可） |

動画の隣に置いた `動画名-landscape.jpg` / `動画名.jpg` / `動画名-thumb.jpg` / `動画名-poster.jpg` や `動画名.nfo`、
`動画名.trickplay\`（Jellyfin などの形式）も読み込めます。`.thumbs` などへまとめて移すには
「[付属ファイルの整理](#付属ファイルの整理)」を参照してください。

MKV などに内蔵されたテキスト字幕（SRT / ASS）も選択できます。画像字幕（PGS / DVD 字幕）には未対応です。

### NFO（メタデータ）

Kodi / Jellyfin 形式の NFO ファイルに対応しています（UTF-8 / Shift-JIS）。

| ファイル | 対象 |
| --- | --- |
| `.nfo\動画名.nfo` | その動画（`<movie>` / `<episodedetails>`） |
| `movie.nfo` | フォルダ内の動画が 1 本だけのとき、その動画 |
| `tvshow.nfo` / `season.nfo` | そのフォルダ（シリーズ・シーズン） |

どれも `.nfo` フォルダ内と動画の隣のどちらに置いても読み込みます（`.nfo` フォルダ内が優先）。
タイトル・あらすじ・年・放送日・評価・ジャンル・制作・監督・出演者・原題を表示します。
`<season>` / `<episode>` があれば話数順に並びます。
`<art>` の `<landscape>` → `<thumb>` → `<art>` の `<poster>` の順で、ローカル画像のパスがあればサムネイルに使います。
検索はタイトル・ファイル名・原題が対象です。

### お気に入り

動画や女優のページの「お気に入り」ボタンで登録でき、サイドバーの「お気に入り」に一覧が出ます（ユーザーごと、`data/favorites.json`）。
女優は別名のどれで登録しても同じ女優として扱います。

### メタデータの編集

動画の詳細画面のサムネイル右上の ✎ ボタン（管理者のみ）で、サムネイル・タイトル・原題・並べ替え用タイトル・発売日・出演・制作・ジャンル・監督を編集できます。

- 出演・制作・ジャンルは、ライブラリで使われている名前から選べます（使われている数の多い順。入力すると絞り込み、候補に無い名前は Enter で追加）
- 年は発売日の年を自動で書き込みます

- 保存先は `.nfo\動画名.nfo`（Kodi / Jellyfin と同じ形式、UTF-8）。無ければ新しく作ります
- 既存の NFO は編集した項目だけを書き換え、それ以外（`<art>`・`<fileinfo>`・出演者の役名や画像など）はそのまま残します
- 動画の隣の `動画名.nfo` や `movie.nfo` を使っていた場合は、その内容を引き継いで `.nfo\動画名.nfo` に保存します
  （動画の隣の `動画名.nfo` は削除、`movie.nfo` は残します）

### サムネイルの変更

メタデータの編集画面（✎）の「サムネイルを変更」から次の操作ができます。

- スライダーで動画の場面を選んで設定する
- 画像ファイル（JPEG / PNG / WebP）をアップロードする
- 画像を削除する（自動生成に戻る。削除した画像は元に戻せません）

再生中は右上のカメラボタンで、今の場面をそのままサムネイルに設定できます。
設定した画像は動画フォルダの `.thumbs\動画名.jpg` に JPEG で保存されます（既にある場合は上書き）。

サムネイルは次の優先順で決まります: `.thumbs\動画名.jpg` → 動画の隣の画像ファイル → NFO の画像 → 自動生成

### シークバーのプレビュー（トリックプレイ）

再生中にシークバーへマウスを乗せる（スマホではドラッグする）と、その位置の場面が表示されます。

- `.trickplay\動画名.trickplay\` があればそれを使います（Jellyfin と同じ形式: `320 - 10x10\0.jpg` …）
- 無い場合は、初めて再生したときにバックグラウンドで作成して `.trickplay` に保存します
  （キーフレームだけを読むので、2 時間の動画でも数分程度です。作成中はプレビューが出ません）

### 出演者・発売日・生年月日の取得

品番（`MILK-163` など）で出演者・発売日・生年月日を取得し、NFO に書き込むツールです。

- [r18.dev](https://r18.dev/)（FANZA の作品情報を公開しているデータベース）: 出演者・発売日
- [av-wiki.net](https://av-wiki.net/)（素人・企画作品の出演者のまとめサイト）: r18.dev に出演者が無い作品の出演者と、女優の生年月日
- どちらでも見つからない作品は、ファイル名の末尾の名前（`… 青井いちご` `(一条みお)` など）を出演者の候補にします
- 独自の品番が別の作品と同じ場合があるため、見つかった作品のタイトルがファイル名と似ていないものは使いません

1. `node tools\fetch-actors.js` … 取得して確認用の一覧 `data\actors-review.csv` を作ります（NFO は変更しません）
   - 対象は設定済みのライブラリ（`Animetion` を除く）。`node tools\fetch-actors.js D:\Video` のようにフォルダも指定可
   - r18.dev は 1 秒、av-wiki.net は 1.5 秒に 1 件ずつ検索します。結果は `data\cache\r18` `data\cache\avwiki` に保存し、2 回目以降は再利用します
   - `--no-web` を付けるとネットに接続せず、ファイル名からだけ取得します。`--test MILK-163` で 1 件だけ試せます
2. 一覧を Excel などで開き、「適用」列を確認します。`○` の行が書き込まれ、`?`（ファイル名からの候補で要確認）は
   `○` か `×` に変えてください。出演者（`／` 区切り）・生年月日・発売日も直せます
   - `node tools\fetch-actors.js --births` で、`○` の行の生年月日が空の出演者を女優名で検索して埋めます
     （av-wiki.net の女優ページ → このAV女優の名前教えてwiki → 無修正動画エログ → 口コミ屋 → Wikipedia の AV 女優の記事 → みんなのAV の女優ページの順。別名でも探します。取得元は「備考」列）
     みんなのAV は初回だけ五十音の女優一覧を全部読むため 30 分ほどかかります（`data\cache\minnano` に保存して 30 日間再利用）
   - `node tools\fetch-actors.js --titles` で、出演者が空の行を av-wiki.net の品番検索・タイトル検索で埋めます
     （品番で確かめられたものは `○`、タイトルだけで見つけたものは `?`）
3. `node tools\fetch-actors.js --apply` … `○` の行を NFO に書き込みます
5. `node tools\fetch-actors.js --photos` … 女優の画像を、その作品の動画フォルダの `.actors\名義.jpg` に保存します。
   NFO の `<actor><thumb>` にある画像（URL・Jellyfin のフォルダなどのローカルの画像）を取り込み、無ければ
   FANZA の女優画像 → このAV女優の名前教えてwiki の画像 → 無修正動画エログ の写真 → みんなのAV の写真の順に探します（既に `.actors` に画像がある名義は変更しません。別名の女優は画像を共有）
6. `node tools\fetch-actors.js --fix-thumbs` … NFO の `<actor><thumb>` が Jellyfin のフォルダや存在しないファイルを指している場合、
   `.actors` の画像のパスに書き換えます（URL や実在する画像はそのまま。書き換える前の NFO は `data\backup` に保存）
7. `node tools\fetch-actors.js --javtube` … TFF（Tokyo Face Fuck）でローマ字名のままの行を、javtube.com の女優ページ
   （タイトルの日本語名・作品番号）で日本語名にします（作品番号まで一致したものは `○`、名前だけのものは `?`）
8. `node tools\fetch-actors.js --spermmania` … Spermmania（`001-Yui Kawagoe.mp4`）の行を、1pondo.com の作品ページ
   （タイトルの日本語名）で日本語名にします（作品番号まで一致するので `○`。見つからない女優はローマ字名のまま `?`）
4. `node tools\fetch-actors.js --aliases` … 同じ女優の別名の候補（r18.dev・av-wiki・tokyo-face-fuck.com・Wikipedia・このAV女優の名前教えてwiki・みんなのAV・口コミ屋）を
   `data\people-aliases-suggested.json` に書き出します。Micol は 2 か所以上の情報源で一致した組を自動で同じ女優にまとめ、
   残りは女優一覧の「別名の候補を確認」で「同じ女優」「違う」を選べます

### 女優の別名

同じ女優の名義（別名）は 1 人にまとめて表示します（作品数がいちばん多い名義が代表名）。

- 女優ページに別名と、作品ごとの名義（「三崎あかり 名義」など）を表示します。別名で検索しても見つかります
- 生年月日はどの名義で設定しても共有され、当時の年齢に使われます
- 年齢でも検索できます。検索欄に「20歳」「20-25歳」と入れると、現在その年齢の女優と、出演者が当時その年齢の作品が出ます
  （「当時20歳」は作品だけ、「現在20歳」は女優だけ）。女優一覧の絞り込み欄では現在の年齢で絞り込めます
- 管理者は女優ページの写真右上の ✎（写真・別名・生年月日・別の女優との統合）で直せます（外した名義は候補から再び取り込まれません）
- 女優の画像は、動画フォルダの `.actors\名義.jpg` → NFO の `<thumb>` のローカルの画像 → `<thumb>` の URL の順に使います
- 別名は `data\aliases.json` に保存します。NFO の出演者名（作品ごとの名義）は変更しません

- 出演者が既に入っている NFO は出演者を変えず、生年月日だけを足します
- 発売日（`<premiered>` / `<year>`）は NFO に無い場合だけ書きます
- 生年月日は `<actor><birthdate>` に書きます。女優ページで設定した生年月日があれば、そちらが優先されます
- 未成年を性的に扱うタイトルの作品は対象外です

### 付属ファイルの整理

動画の隣にある画像・NFO・トリックプレイ（Jellyfin などの形式）を `.thumbs` / `.nfo` / `.trickplay` に移すツールです。

```
node tools\migrate-sidecars.js            … 何をするかの確認だけ（ファイルは変更しない）
node tools\migrate-sidecars.js --apply    … 実行
```

- 対象は設定済みのライブラリすべて（`node tools\migrate-sidecars.js --apply D:\Video` のようにフォルダも指定可）
- 画像は `動画名-landscape` → `動画名` → `-thumb` → `-poster` → `-fanart` の順で最初に見つかったものを
  `.thumbs\動画名.jpg` にします（PNG / WebP は JPEG に変換）。残りの画像も同じ名前のまま `.thumbs` に移します
- 画像がどの動画のものかは、ファイル名が「動画名 + 接尾辞」と完全に一致するかで判断します
- フォルダ内の動画が 1 本だけの場合は、`landscape.jpg` などもその動画の画像とみなし、`movie.nfo` も `.nfo` に移します
  （`.nfo\動画名.nfo` が既にあれば `.nfo\movie.nfo`）
- NFO 内の画像パスは移動後のパスに書き換えます
- 移動先に同名のファイルがある場合や、対応する動画が無いファイルは移動せず、一覧に表示します
- 何度実行しても問題ありません。移動の記録は `data\logs\migrate-sidecars-*.json` に残ります

## 再生方式

ブラウザの対応状況に合わせて自動で選びます（プレーヤー右上に表示）。

| 方式 | 内容 |
| --- | --- |
| ダイレクト再生 | ファイルをそのまま配信（MP4 / WebM で H.264・HEVC・VP9・AV1 など） |
| リマックス | 映像・音声はそのままで MP4 に詰め替え（MKV の H.264 + AAC など） |
| 音声変換 | 映像はそのまま、音声だけ AAC に変換（AC3 / DTS など） |
| トランスコード | 映像も H.264 に変換（10bit H.264、MPEG-4、非対応ブラウザでの HEVC など） |

再生できなかった場合は自動でトランスコードに切り替わります。プレーヤーの「再生方式」から手動で切り替えることもできます。
設定画面で GPU エンコーダー（NVIDIA NVENC / Intel Quick Sync / AMD AMF）を選ぶと、トランスコード時の CPU 負荷を下げられます。

## 別の PC で常時起動する（git で手動更新）

サーバー用の PC で一度セットアップすれば、PC 起動時に自動で立ち上がります。
GitHub のリポジトリに push した変更は、設定画面の「今すぐ更新」で取り込めます。

### セットアップ（サーバー用 PC で 1 回だけ）

1. PowerShell を開き、次の 1 行を貼り付けて実行します（管理者で開く必要はありません）
   ```
   irm https://raw.githubusercontent.com/fukata9991/Micol/main/setup.ps1 | iex
   ```
   - Git・Node.js・FFmpeg が無ければ、winget でインストールするか確認されます
   - `C:\Micol` にダウンロード（git clone）されます
   - 管理者権限の確認が出たら「はい」を選ぶと、常駐登録まで行われます
2. 表示された `http://localhost:8420` をその PC のブラウザ（または同じ LAN の PC）で開き、管理者アカウントを作成して、設定からライブラリを追加します

インストール先を変える場合や、NAS を使う場合（後述の `-StorePassword`）は次のように実行します。

```
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/fukata9991/Micol/main/setup.ps1))) -Path D:\Micol -StorePassword
```

<details>
<summary>手動でセットアップする場合</summary>

1. Node.js・Git・FFmpeg をインストールします（`node` `git` `ffmpeg` `ffprobe` に PATH を通す）
2. リポジトリを clone します
   ```
   git clone https://github.com/fukata9991/Micol.git C:\Micol
   ```
3. `C:\Micol\install-service.cmd` をダブルクリックします（管理者権限の確認が出たら「はい」）

</details>

これで次のように動きます。

- PC の起動時に自動で起動します（Windows へのログオンは不要で、ウィンドウも表示されません）
- サーバーが落ちたら自動で再起動します
- ファイアウォールで待ち受けポートを許可します（プライベートネットワークのみ）

ライブラリの設定・視聴履歴・サムネイルは `data/`（git 管理外）に保存されるので、更新しても消えません。
設定画面の「アップデート」に、今動いているバージョン（コミット）が表示されます。

### 更新のしかた

1. 開発用 PC でコミットして push します
   ```
   git push
   ```
2. Micol の設定画面の「アップデート」で「更新を確認」を押すと、新しいコミットの一覧が表示されます
3. 「今すぐ更新」を押すと `git pull` してサーバーが再起動し、画面が自動で読み込み直されます

更新は、ボタンを押したときだけ行われます（自動では更新されません）。
サーバー用 PC のリポジトリで直接コミットしていると更新できません。サーバー用 PC では変更しないでください。
`start.bat` で起動している場合は、ボタンでは更新できません。`git pull` してから起動し直してください。

### 補足

- **NAS などネットワーク上のフォルダ**をライブラリにする場合は、パスワードを保存する方式で登録してください。
  標準の方式（パスワードなし）では、ネットワークドライブにアクセスできません。
  セットアップ済みの場合は、次のコマンドで登録し直せます。
  ```
  install-service.cmd -StorePassword
  ```
- 設定の変更・更新は、管理者ユーザーでログインすれば、どの端末からでも行えます
- ログは `data/logs/micol.log` に出力されます
- 常駐を解除するには `uninstall-service.cmd` を実行します（`data/` は残ります）

`data/config.json`（初回起動時に作成）

| `port` | `8420` | 待ち受けポート |
| `host` | `0.0.0.0` | `127.0.0.1` にするとこの PC からのみアクセス可 |
| `ffmpegPath` / `ffprobePath` | `ffmpeg` / `ffprobe` | PATH に無い場合はフルパスを指定 |

`data/` には設定・視聴位置・サムネイル・ログが保存されます。削除すると初期状態に戻ります。

## 制限事項

- インターネットに公開する場合（Cloudflare Tunnel など）は、推測されにくい長めのパスワードを使ってください。
  Cloudflare Access などで手前にもう一段の認証を置くと、より安全です
- iPhone / iPad の Safari では、ダイレクト再生以外（リマックス・トランスコード）は再生できないことがあります
